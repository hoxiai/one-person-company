## 一、四类岗位，四种死法

| 岗位 | 最容易死在哪 | 要补的短板 |
|---|---|---|
| 💻 **研发 / 程序员** | 把一个**没人买的系统**架构得无比庞大 | 商业嗅觉、分发意愿、MVP 断舍离 |
| 🎯 **产品经理 / 业务** | 习惯大兵团作战，单干时**卡在环境配置和部署跑崩** | 端到端 AI 交付、算力账本、极简验证 |
| 🎨 **UI / UX 设计师** | 数据没跑通、钱没收到**就先放弃了** | 技术栈断舍离、模板资产复用、自动结算 |
| 📈 **运营 / 增长** | 手工一对一服务，**享受不到软件的复利** | 微工具产品化、自动化流水线、高毛利模型 |

> 认领你的那一行。**看清楚自己的死法，比学会任何新技术都重要。**

## 二、五维能力模型

| 维度 | 考察什么 |
|---|---|
| **商业与验证嗅觉** | 能否在第一天找到真需求、**敢于收费**、用 MVP 验证付费意愿 |
| **全栈 AI 交付力** | 善用 AI 杠杆，端到端打通「代码 + 部署 + 支付」闭环 |
| **流量与分发力** | 公开构建、**破除营销羞耻**、冷启动获客与 SEO |
| **成本核算与杠杆** | 算清 Token 账本、掌握模型平替降费、拒绝重复造轮子 |
| **跑道与心智韧性** | 现金安全跑道、面对零反馈的抗挫力、**严格止损** |

**五维里最容易被低估的是第三项。** 大多数技术出身的人，产品做完了才开始想怎么让人知道——
而那时候钱和心气通常都已经烧掉一半了。

## 三、十二问快速自测（离线版）

每题答「是」记 1 分。**答不上来的一律记 0**，别给自己放水。

**商业与验证**
1. 你能说出你要服务的**具体一个人**是谁（不是「开发者」这种群体）吗？
2. 你有没有在写第一行代码之前，**问过至少 5 个真实用户**愿不愿意付钱？
3. 你的产品有明确定价吗（不是「先免费再说」）？

**交付力**
4. 你能一个人在**一周内**把一个想法做到线上可访问吗？
5. 你的部署是不是 `git push` 就自动上线（而不是手动 scp）？
6. 你能独立处理域名、SSL、支付回调这些「非核心」的破事吗？

**分发力**
7. 你有没有一个**你自己的**分发渠道（博客 / X / 公众号 / 群）？
8. 你能坦然地公开说「我做了个东西，卖 XX 元」吗？
9. 你上一个项目上线后，**主动**告诉过多少人？超过 20 个吗？

**成本与心智**
10. 你知道自己上个月在 AI 上花了多少钱吗（**精确到个位数**）？
11. 你的现金跑道够撑几个月？**说得出具体数字**吗？
12. 你有没有给当前项目设一条**明确的止损线**（时间或金额）？

### 计分

| 分数 | 判断 |
|---|---|
| **10–12** | 已就绪。缺的是开始，不是准备。 |
| **7–9** | 短板集中在某一两维——回头看你答 0 的题，那就是你的功课。 |
| **4–6** | 典型的「技术就绪、商业未就绪」。**先别写代码，先去找 5 个愿意付钱的人。** |
| **0–3** | 别急着辞职。先在业余时间跑通一个能收到钱的小闭环，哪怕只赚 100 块。 |
